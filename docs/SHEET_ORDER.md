# Excelシート順による章立て

## 目的

ExcelとMarkdownを順番に見比べてチェックできるようにする。文書全体を業務テーマ別に組み替えず、シートの並びを章立ての基準とする。内容の表現は、人が書く仕様書のような文章・表・リスト・HTML・Mermaidとする。

## 本文の構成

元ブックの保存済みタブ順を読み、非表示シート・凡例・変更履歴等を除外してから、残ったシートに1から連番を付ける。名前順・sheetId順・内部XMLファイル名順には並べない。

H1は文書タイトル1個。H2は `## 1. 表紙` のような「連番＋元シート名」。シート内の見出しはH3以下とする。シート名末尾の表示用空白を省略しても、対応付けには元の完全な名前を使用する。

画面HTMLは画面レイアウトの章、DFDはDFDの章、イベント表はイベント説明の章に置く。複数シートを「画面と操作」「イベントとデータフロー」等の独自の章に統合しない。同一シート内の段落化や論理列への整理は可能だが、意味・対応関係を変更しない。

質問や確認記録だけを持つシートも、本文の該当位置に短いQA参照を置く。QA本文を本文へ戻したり、空欄を架空の仕様で埋めたりしない。除外シートには章を作らない。

## QAと報告

QAは主な出典シートごとに、元のシート順で配置する。章番号は本文と揃え、QAがない章は省略する。Q01等の既存ID・選択肢・回答内容・状態は変えない。複数シートに関係する質問は一度だけ掲載し、出典を併記する。

報告の出典対応表は元シート順に並べる。元ブックのタブ位置と本文の章番号を併記する。「結果」「対象範囲と読み方」「検証結果」等はreport内に置き、outputの章には追加しない。

## 維持するルール

非表示シート・行・列、凡例、変更履歴は対象外。保存先はoutput・qa・reportで、入力からの相対サブフォルダとファイル名を維持したUTF-8（BOMなし）の.md。mainを直接操作し、元Excelは変更しない。画面は静的HTML、確認済みのフローはMermaid、吹き出しは対象に結び付くコメントと可視注記にする。質問の選択肢を確定仕様として扱わない。

## 組立て・検証用プログラム

`src/sheet_order.py` は、可視範囲を確認済みのシート別本文をJSONで受け取り、元のタブ順に組み立てる。セル、画像、図形を自動解釈するプログラムではない。本文断片を作る段階で可視範囲・凡例区画・QAの分離を済ませる必要がある。

```bash
python -m src.sheet_order input/spec.xlsx --sections reviewed_sections.json -o output/spec.md
python -m unittest discover -s tests -p test_sheet_order.py -v
```

JSONは `title` と `sections` を持ち、`sections` のキーは末尾空白も含めた元シート名、値はH3以下の見出しを含む確認済みMarkdown本文。対象シートの不足・余剰、空の本文、断片中のH1/H2はエラーとする。

合格には、対象シートとH2の順番・名称・件数の一致、元シートへの内容帰属、HTML・Mermaid・表・QA回答の保持、リンク先の存在が必要。以前のテーマ別候補が新基準で不合格でも、元の仕様内容自体が失われたことを意味しない。
