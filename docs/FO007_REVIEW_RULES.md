# FO-007で追加確認した変換ルール

既存のAGENTS.mdの出力先・可視範囲・章順・はじめに・HTML枠外注記・Mermaid独立評価を維持する。本書はそれらを緩和しない。

## Excelの非表示と、仕様としての画面非表示を区別する

保存状態が非表示のExcelシート・行・列は対象外。一方、表示された設計書に「請求書を非表示にする」「個別画面では仕入先・名前を非表示」と記載されている場合、それはアプリケーションの仕様なので保持する。文字列に「非表示」が含まれることだけで除外してはいけない。

一覧、個別、決済等で同じ項目名が使われても、表示・入力可否は画面ごとに保持する。FO-007では主画面は入力不可、決済画面の4項目は更新可。この違いを共通化によって消さない。

## 埋込OLEの保存済みプレビュー

ワークシートのoleObject/objectPr、画像Relationship、同一shapeIdのVMLを確認する。DrawingMLにhiddenなOLEプレースホルダーがあっても、表示中のVMLプレビューが別に存在することがある。プレースホルダーだけを見て可視プレビューを失わない。

反対に、非表示シート・非表示VMLのデータを復活させない。行列と重なる境界・欠落した表示情報はREVIEW_REQUIREDとする。実行ファイル・マクロ・OLEアプリを起動せず、リンクされた保存済み画像だけを扱う。埋込パッケージの全ページや非表示データを取得して仕様を補完しない。

`src/ole_preview.py` はこの確認を補助する追加モジュールで、既存の描画抽出器を置換しない。画像の読解と目視確認は別工程であり、メタデータ検出だけを変換完了としない。

## 画面例と原資料の相違

同一の画面例が繰り返される場合、全値は主例に保持し、他の画面では抜粋を明示する。実データ件数の制限や初期値を創作しない。スクリーンショットで省略表示された名称の続きを補完しない。

数値型／日付表示、物理名の綴り、財務タグの格納スロット、結合式、追加項目の配置が矛盾または未定義なら、原表記を出典ごとに保持し、選択式QAへ分離する。描画を成功させるために仕様の曖昧さを消さない。

## 非回帰

新しい資料への対応は既存のFO-006の本文・QA・報告を書き換えない。共有処理を変更する場合は変更前のFO-006の出力とテストを固定して再実行する。取得できず検証を省略する場合は未実施と明記し、PASSとしない。

本実行では共有変換器・Mermaid評価器は変更せず、OLE検出補助とFO-007専用の独立内容検査を追加した。FO-006は既存成果物のハッシュと3図の実レンダリングを確認した。この確認を元Excelからの完全再変換試験と混同しない。

## 再検証

```bash
python -m unittest discover -s tests -p test_ole_preview.py -v
python -m src.ole_preview input/FO-007_詳細設計書_仕入先トランザクション画面.xlsx --json /tmp/fo007-ole.json
python tools/review_fo007.py input/FO-007_詳細設計書_仕入先トランザクション画面.xlsx output/FO-007_詳細設計書_仕入先トランザクション画面.md qa/FO-007_詳細設計書_仕入先トランザクション画面.md --json /tmp/fo007-content.json
python -m src.independent_evaluate output/FO-007_詳細設計書_仕入先トランザクション画面.md --acceptance-json /tmp/fo007-content.json --expected-count 2 --asset-map /path/to/local-mermaid-assets.json --browser-path /path/to/chromium --json /tmp/fo007-final.json
```

FO-007内容検査はbeautifulsoup4を使用する。これは対象ファイルSHAを固定した受入検査で、別版・別仕様書へ無条件にPASSを与えるものではない。Mermaidのオフライン実行準備は既存のdocs/MERMAID_VALIDATION.mdを参照。
