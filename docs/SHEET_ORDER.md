# 「はじめに」とExcelシート順による章立て

## 目的

表紙・共通ヘッダー・共通内容を冒頭の「はじめに」に集約し、以降はExcelと順番に見比べてチェックできる章立てにする。本文の表現は文章、表、リスト、HTML、Mermaidを用い、Excelの空白グリッドは再現しない。

## 本文の構成

元ブックの保存済みタブ順を読み、非表示シート・凡例・変更履歴等を除外する。先頭の表紙章は `## 1. はじめに` とし、独立した「表紙」章は残さない。以降は `## 2. 処理概要` のように連番と元シート名を維持する。名前順・sheetId順・内部XMLファイル名順には並べない。

H1は文書タイトル1個。章内はH3以下。表紙の見出しを変えても、対応付けには元のシート名とアンカーを保持する。シート名末尾の表示用空白を省略しても、キーは完全な原名を使用する。先頭に表紙がないブックへ、未確認の表紙やメタデータを勝手に追加しない。

## はじめにへ集約する内容

| 区分 | 集約方法 |
|---|---|
| 表紙の文書情報 | 文書名、プロジェクト、宛先、版数、作成会社などを記載する。 |
| 共通ヘッダー | システム、機能ID・名称・分類、作成日・作成者、更新日・更新者を集約する。同じ事実を複数表へ重複記載しない。 |
| 承認情報 | 承認日・承認者・確認日・確認者を記載し、作成更新情報と役割を混同しない。 |
| 共通仕様 | 内容・条件・単位・適用範囲が確認できた共通部分だけを、安定したID・アンカー付きで記載する。各適用章からリンクする。 |

シート固有の目的、イベント、項目定義、テーブル定義、画面例、注記は、そのシートの章に残す。一般的に見える文章でも、根拠なく全章共通へ広げない。共通化で参照関係を失わせない。

異なるヘッダー値や仕様の例外は黙って統一しない。共通情報に適用範囲を示し、固有の差分は該当章に保持する。矛盾・質問本文はQAへ置き、本文には短いQA参照を残す。例えば「正数のみ」と0を含む例示がある場合、共通化で0の可否を決めない。

図形・HTML・Mermaid・元の吹き出しは移動しない。共通制約を引用する吹き出しも、原文と対象の対応を優先して残す。重複文言の単純削除や自動要約ではなく、出典を確認した集約とする。

## FO-006での適用例

```text
1. はじめに
   1.1 文書・機能情報
   1.2 作成・更新・承認情報
   1.3 共通事項
       CR01 支払方法・請求金額の重複登録
       CR02 請求金額・支払サイトの負数入力
2. 処理概要
3. テーブル一覧
4. DFD
…以降は元のシート順…
13. プログラムフロー図
```

処理概要・画面項目説明・補足説明は共通事項へリンクする。一意インデックスは補足説明、操作と入力可否は画面項目説明に残す。正数／0、全角ｍ／半角m、フォーム名などの表記差は回答前に統一しない。

## QAとreport

QAは主な出典シート順に配置し、章番号を本文と合わせる。表紙・共通ヘッダーに関する第1章のグループ名は「はじめに」。Q01等の既存ID・選択肢・回答・状態は変えない。共通仕様を移動しても関連QAを重複掲載・改番しない。

reportの出典対応表は元シート順に並べ、元タブ位置と本文の章番号を併記する。共通化で移動した情報は、出典・集約先・適用章を別途記載する。「対象範囲と読み方」「結果」「検証」はreportだけに置く。「はじめに」を変換作業の報告ページにしない。

## 組立て・検証

`src/sheet_order.py` は可視範囲を確認済みのシート別本文をJSONで受け取り、先頭の表紙だけ見出しを「はじめに」にする。共通化する内容の抽出・意味判定は行わない。呼出側で共通情報を原シートキー「表紙」の断片へ集約し、元章へ参照を置く。セル・画像の汎用自動解釈エンジンではない。

```bash
python -m src.sheet_order input/spec.xlsx --sections reviewed_sections.json -o output/spec.md
python -m unittest discover -s tests -p test_sheet_order.py -v
```

JSONは `title` と `sections` を持ち、`sections` のキーは原シート名、値はH3以下の確認済み本文。対象外・不足・余剰キー、空本文、H1/H2の混入はエラーにする。

受入確認では、「はじめに」と後続章の順番、共通情報の一回記載、元の値と適用範囲、差分の保持、HTML・Mermaid・注記・QAの保持、リンク先を確認する。非表示内容や凡例・変更履歴は評価対象に含めない。UTF-8（BOMなし）の同名.mdをoutput・qa・reportへ保存し、mainへの保存後に再取得する。
