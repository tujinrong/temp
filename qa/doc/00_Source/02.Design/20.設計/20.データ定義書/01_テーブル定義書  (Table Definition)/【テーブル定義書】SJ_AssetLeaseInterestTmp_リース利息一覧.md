### Q01 PK指定とインデックスの重複許可の関係

**出典**：テーブル定義：No.1 LeaseID、No.2 BookType／その他定義：インデックスNo.1 SJ_LeaseIDIdx

**背景**：LeaseIDとBookTypeはPK・必須がともにYES。一方、同じ2項目LeaseID,BookTypeを持つSJ_LeaseIDIdxの重複許可はYesと記載されている。本文では両方を原資料どおり保持し、一意制約の実装を推測していない。

**質問**：LeaseIDとBookTypeの組に対する一意性と、両欄の扱いはどれですか。

| 選択肢 | 回答内容 |
| --- | --- |
| A | 2項目の組を一意とし、インデックスの重複許可をNoに修正する。 |
| B | 同じ組の複数行を許可し、2項目のPK指定を見直す（一意キーがある場合は補足）。 |
| C | 両方の記載を維持する（PK欄の意味や別の一意制約がある場合は補足）。 |
| D | その他（正式なキー・インデックス定義を補足）。 |
| E | 未定・要調査。 |
