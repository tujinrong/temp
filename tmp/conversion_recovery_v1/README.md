# 変換処理の中断・再開対策（試行版）

既存のAGENTS.md、docs、src、tools、testsは変更しない。本補助処理はtmp配下だけに置く。変換の品質条件を緩めるものではなく、作業の消失と無駄な再処理を減らすための試行版である。分析エラーそのものの発生防止を保証しない。

## 処理単位

1ファイルを「入力照合→可視シート単位の抽出→章・図単位の解釈→本文・QA組立→内容検査→HTML検査→Mermaid検査→公開・再取得照合」に分ける。重い工程の直前・直後に保存する。長時間処理を一つの呼出しへまとめない。

## 保存するもの

進捗説明だけでなく、抽出済みの可視内容、確認済み章、本文・QA候補、実行した検証JSON、入力・ルール・使用コードのハッシュを保存する。除外した非表示内容は保存対象に戻さない。まだ生成していないものは欠落として明示する。

`save_stage`は実ファイルを読み取り、内容別のスナップショットとマニフェストを保存する。マニフェストは全ファイルの保存・照合後に置換する。同じ成果物を再登録しても同じスナップショットになる。共有ディレクトリへの同時書込みは行わない。

## GitHubでの耐久化

ローカル保存はLOCAL_ONLYであり、GitHub保存成功ではない。オーケストレーターが実ファイルとマニフェストを同じコミットとしてmainに保存し、コミットから内容を再取得する。`acknowledge_readback`へその実バイト列とコミットを渡し、照合に成功したものだけをREADBACK_VERIFIEDと記録する。補助処理自体はGitHubへ接続しない。単体テストの仮コミットを本番の保存証拠に使わない。

## 再開判定

`validate_stage`がREUSEを返すには、入力等の依存ハッシュと全成果物のサイズ・SHA-256が一致する必要がある。欠落・破損・入力変更・ルール変更・使用コード変更はRERUN_STAGEとして扱い、成功としない。関連する下流工程の依存には上流マニフェストのハッシュを含める。

変換済みファイルは、元の相対パスと入力ハッシュ、本文・QA・reportの保存確認を照合してスキップする。同名でも別版なら使い回さない。工程が失敗した場合は、その工程だけを診断し、同じ失敗を無制限に繰り返さない。

## 完了と削除

最終3ファイルをmainから再取得して照合するまで、チェックポイントを削除しない。完了後の削除は該当実行の中間ファイルだけに限定する。他文書の中間状態・入力・成果物は残す。通常のGit削除では履歴が残る。

この仕組みはバックグラウンドで会話処理を再起動しない。中断後の新しい実行が保存状態を確認し、未完了工程から再開するためのものである。

## テスト

このディレクトリで `python -m unittest -v` を実行する。正常再利用、欠落、破損、依存変更、中途失敗、冪等性、範囲外パス、ローカル／リモート区別、誤った再取得データ、正しい再取得データの10テスト。
